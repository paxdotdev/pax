# Pax Application Instructions

This is a Pax application generated by `pax-cli`. Work in this application
project; do not assume the Pax framework monorepo is available.

## Find Current Pax Guidance

Use the CLI documentation before inventing syntax or architecture:

- `pax-cli docs list`
- `pax-cli docs open "Getting Started"`
- `pax-cli docs open "Template Language & Structure"`
- `pax-cli docs open "Data Binding & Expressions"`
- `pax-cli docs open "Event Handling & Rust Logic"`
- `pax-cli docs search <query>`
- `pax-cli docs examples --list`
- `pax-cli docs examples <example-name>`

The hosted builder primer at `https://pax.dev/ai` is the bootstrap for a
fresh AI-assisted session. This local file is the durable project-level
guidance after the project has been created.

If a Pax command fails because the workstation is incomplete or misconfigured,
pause application work and act as a setup doctor. Inspect the actual command
output and installed versions, then use the CLI Getting Started documentation
to prepare one platform-specific installation and configuration worklist. Ask
for confirmation once, execute the approved worklist as a batch, verify the
result, and rerun the failing command. Return sooner only for an unexpected
blocker or a new decision that the original approval did not cover.

## Author in Two Layers

- `.pax` templates declare UI trees, layout, bindings, events, animation, and
  style. PAXEL expressions inside `{...}` are declarative and side-effect free.
- Rust files own application state, event handlers, data loading, platform
  logic, and other side effects.

Use PAXEL to derive displayed values from state. Route events to Rust when work
must mutate state or interact with the outside world.

Pax source order also defines stacking order: an earlier sibling is drawn above
a later sibling. Check source order before compensating with layout math.

## Work Through the CLI

Run the application from its project root:

```sh
pax-cli run
```

The debug default is `--hot-reload=pax`: `.pax` edits update the mounted app,
while Rust edits require rebuilding and restarting. On web and macOS, opt into
logic reload with `pax-cli run --hot-reload=all` when its rebuild latency is
appropriate for the task.

Use the open-source developer tools to inspect the running result:

```sh
pax-cli dev look
pax-cli dev inspect tree
pax-cli dev --help
```

Prefer observing the actual rendered app over inferring appearance from source
alone. Exercise relevant interactions and inspect the expanded tree when
layout, selection, or event routing is unclear.

Before handing off meaningful work, format the sources and complete a web
build:

```sh
pax-cli fmt
pax-cli fmt --check
pax-cli build --target=web
```
